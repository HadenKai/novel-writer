# 联网检索（创作管家）

管家的联网能力由「工具 + 回合」两部分组成：

1. 模型在回复末尾输出动作 `webSearch`（检索词）或 `fetchPage`（公网 URL）；
2. 服务端真正执行检索/读页，把来源编号后回喂给模型；
3. 模型基于来源重新回答，引用处标注 `[1][2]`；同一轮最多 3 次搜索 + 2 次读页；
4. 来源列表随消息保存，前端在回复下方显示「联网来源 · N」。

检索不会修改书稿；它只把外部资料带进本轮回答。

## 搜索源

| provider       | 配置                                | 说明                                       |
| -------------- | ----------------------------------- | ------------------------------------------ |
| `bing`（默认） | 无需配置                            | 解析 Bing 搜索结果页，中文可达性最好       |
| `searxng`      | `SEARXNG_URL=http://127.0.0.1:8080` | 自建开源元搜索，隐私最好；需开启 JSON 输出 |
| `tavily`       | `TAVILY_API_KEY=...`                | 质量最好，商业 API                         |

选择顺序：显式 `NOVEL_SEARCH_PROVIDER` → 有 `SEARXNG_URL` 用 SearXNG → 有 `TAVILY_API_KEY` 用 Tavily → 否则 Bing。

## 安全边界

- `fetchPage` 只允许公网 `http/https`，拒绝 localhost、内网段、`.local` 与带账号密码的 URL，防止被网页内容诱导访问本机服务；
- 读页上限 1.5 MB / 6000 字符，搜索与读页各有 12s / 15s 超时；
- 检索失败会以「失败记录」回喂模型，模型必须如实说明，不允许编造来源。

## 隐私

检索词会发送到所选搜索服务（默认 Bing）。书稿正文不会随检索请求发送；只有模型主动写进检索词的内容才会离开本机。

## 相关 Skill

- `web-research-protocol`：子问题拆分、多视角检索、读原文、交叉验证、带引用作答；
- `source-verification`：来源分级、时效检查、冲突标注、四档置信度。
