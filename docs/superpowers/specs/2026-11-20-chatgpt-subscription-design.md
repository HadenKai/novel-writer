# ChatGPT Subscription 桌面接入设计

## 目标与范围

在桌面版「设置 → AI 模型 → 添加模型」中增加 **ChatGPT Subscription**。作者通过 Codex 设备码授权后，可以选用订阅连接来测试模型、设置全局默认模型，或为作品指定模型。小说工坊继续负责提示词、上下文、创作管家动作、写作阶段和书稿写入。首版采用用户选定的 Hermes Agent Codex Responses 路线，由小说工坊管理 OAuth，当前范围排除 SIWC、Codex CLI 依赖和独立 Codex App Server。

本设计建议首版限定为桌面、单个已连接的 ChatGPT 账号和工作区。Electron 开发窗口和本地打包的安装版均在「AI 模型」显示标为「实验性」的入口，由用户主动连接。独立 Web 模式沿用现有供应商。本功能成功的标志是作者能从新安装的桌面应用完成授权、测试真实流式生成、写一章并在重启后继续使用连接。用户明确断开连接后，后续请求应提示重新连接。模型额度耗尽或权限不足时，界面要给出对应状态，避免静默调用其他付费连接。

## 已选路线

| 路线                                   | 取舍                                                                                                                            |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **Codex 设备码和直接 Codex Responses** | 用户选定。Hermes 提供了实践参考。适配器可沿用小说工坊现有的 Agent Loop。设备码、模型目录和 ChatGPT Codex 请求格式依赖上游行为。 |
| SIWC 和直接 Responses                  | OpenAI 为开源应用记录了应用授权与模型调用契约，同样支持应用自行刷新和运行 Agent Loop。本阶段沿用用户选定的设备码。              |
| Codex App Server                       | 可以管理 Codex 登录与运行时，代价是要维护独立进程和协议，并处理现有写作上下文及动作边界的衔接。用户已选定现有写作运行时。       |

Hermes 的实现以 Codex OAuth 客户端和 ChatGPT Codex 后端为基础。OpenAI 公布的设备码流程标为 Codex CLI Beta，开源应用的正式订阅接入文档采用 SIWC。上游是否为小说工坊提供长期支持仍有待确认，属于公开发行风险。本次实现按桌面实验功能验收，真实连通性使用明确授权且已启用设备码的账户验证。设计阶段仅核对公开源码和文档。

## 设置界面与模型配置

1. 在 `src/pages/Settings.tsx` 现有服务商选择中新增 ChatGPT Subscription。用户选择后看到账号连接状态，以及「连接 ChatGPT」或「断开连接」。使用现有设置页表单、对话框和错误样式。已连接后，显示名称和模型 ID 成为模型表单的输入。服务端固定授权及推理目标，用户只需选择订阅可用模型。设备码窗显示一次性验证码、复制按钮、打开官方验证页面和取消按钮。
2. 等待授权、授权完成、取消、过期、账号未开启设备码、网络重试和需重新连接分别有文本状态。账号连接状态与单个模型配置分开，一个连接可供多条模型配置使用。模型可从支持的账号目录选择。若目录接口当下不可用，允许填写上游兼容的模型 ID，并通过「测试连接」判断是否可用。
3. `src/types.ts` 与 `server/models.mjs` 增加显式订阅供应商类型。已有 OpenAI、Gemini 和本地模型按原方式读取、验证及保存。订阅模型保存现有模型 ID、显示名称、默认标记、适用的推理设置和非敏感连接引用。模型设置接口仅返回白名单字段。当前通用的 API Key 拉取和批量导入按钮适用于已有供应商，订阅用自己的账号模型目录入口。
4. 删除单个模型只删除该模型配置。断开账号保留已有模型记录及作品绑定，并标为需要连接。重新授权同一账号工作区可恢复上述模型。换账号或工作区时，由用户明确改绑已有模型。已选模型的授权、额度或模型权限错误应直接反馈，现有的默认模型选择仅用于调用方未指定有效模型配置的场景。

## 设备码和凭据生命周期

- Electron 主进程通过可信 IPC 接收开始、取消、查询状态和断开请求。每次连接尝试有独立 ID 和到期时间。主进程请求设备码并在系统浏览器打开固定的 OpenAI 验证链接，按上游规定的间隔轮询。验证码只在当前会话显示。短暂网络故障在授权期限内有限重试，拒绝或过期会结束本次尝试。取消、关闭应用或新的尝试使旧结果失效。授权信息在上游页面输入。
- 凭据由 Electron 主进程持有，通过 `safeStorage` 加密，放在应用数据目录的独立原子写入文件中。加密不可用时提示无法保存连接。模型配置与渲染进程只接收凭据引用、连接状态和必要的账号显示信息。OAuth 令牌与设备授权内部标识排除在模型 API、导出备份、支持诊断和日志之外。应用通过自己的授权建立会话，凭据存储从小说工坊自身读取。
- 请求前检查访问令牌到期时间。按账号对刷新去重，并原子保存新令牌对。对在流开始前收到的 401 可做一次有界刷新重试，刷新撤销或 `invalid_grant` 将连接标记为需重新授权。临时网络故障、限额和模型权限问题分别在界面显示。断开连接会清除本机凭据并立即拒绝新请求，取消进行中的授权或刷新。已发出的生成请求继续遵循原有取消机制，较早的 OAuth 响应不能恢复已断开的连接。
- Electron 与 Express 同进程。生产模式已有每次启动生成的本地 API 令牌，桌面开发模式目前缺少这层校验。实现时让 Electron 开发窗口请求也使用同样的本地 API 令牌，由可信窗口发出请求并经 Vite 转发，Vite 不持有或生成凭据。独立 Web 调试模式保持现有启动方式，且无订阅凭据可用。验收覆盖普通本地网页访问开发端口时无法借用已连接账户发起推理。

## Responses 适配器与写作流程

- `server/ai-transport.mjs` 的 `streamChat` 分发至独立订阅传输实现。其输入沿用现有模型连接配置和 `AbortSignal`，运行时凭据按连接引用获取。按照 Hermes Codex Responses 的请求形态，把系统提示转换成 `instructions`，把有序消息及受支持的图片转换成 `input`，逐次发送当前模型所需上下文。使用流式请求和 `store: false`，省略 `max_output_tokens` 和 `temperature`，按订阅模型能力映射推理等级。现有提示词中的目标字数和上下文裁剪继续生效。以 Responses 的结束事件判断显式截断，流超时和用户取消仍有效，应用不按估算 token 数截断已收到的正文。
- 适配器把正文增量、可用的推理摘要、正常结束、截断和失败转换为应用已有的输出契约。区分显式截断与 SSE 中途断开，避免将不完整结果表示为成功。用户取消向下传播到 HTTP 请求。已收到模型正文后，断流会报告给现有写作任务流程，避免自动重放导致正文重复。模型权限和额度错误不触发 OAuth 刷新。
- `server/app.mjs` 的章节 Agent、写作任务和管家仍通过 `streamChat` 调用模型。应用继续解析并校验管家动作、管理确认和可撤销写入。首版沿用现有 prompt 驱动动作协议及本机会话状态。连接测试严格选择当前条目的模型并发送短 Responses 流，测试结果明确表示授权、模型或请求错误。
- 具体文件拆分、IPC 命名、SSE 解析复用方式及模型目录请求细节由实现计划根据现有模块和 Hermes 参考实现决定。凭据流和模型传输独立测试，使授权协议或上游地址调整能够局限在供应商代码。

## 验收

| 验收对象           | 预期                                                                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 设备码             | 模拟授权等待、成功、过期、取消、有限网络重试。已取消的旧响应无法写入凭据。                                                                                       |
| 会话               | 重启恢复，多个请求共用一次刷新，新令牌对原子替换，断开后无法刷新或发起订阅请求。刷新失效提示重新授权。                                                           |
| 本地边界           | 凭据落盘加密，公开模型响应、日志和备份中没有令牌。Electron 开发和生产窗能用订阅，普通网页的未验证请求和独立 Web 无法使用桌面凭据。                               |
| Responses          | 模拟系统提示、消息历史、图片能力、SSE 分片、终止、明确截断、断流、额度和权限错误，以及出现增量后的取消。测试连接命中正确模型。                                   |
| 旧配置             | 旧模型数据继续可读，OpenAI、Gemini、本地模型的测试和现有流程仍通过。运行类型检查、构建和相关测试。                                                               |
| 有授权的端到端验证 | 在桌面从零连接自己的账号，选择可用模型，运行短测试、长章节生成与管家问答。重启后复测连接，再验证断开状态。记录真实失败或上游限制，避免用模拟结果代替连通性验证。 |
