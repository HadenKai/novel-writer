# 本地模型与写作 Agent

这一版补上两块能力：**让本机模型能直接当写作引擎**，以及把「写一章」从一次性调用
升级成可自检、可回退的多阶段流程。

---

## 一、本地模型接入

### 支持的服务

| 服务                  | 默认地址                    | 说明                                           |
| --------------------- | --------------------------- | ---------------------------------------------- |
| Ollama                | `http://127.0.0.1:11434/v1` | 老版本没有 `/v1/models` 时自动退回 `/api/tags` |
| LM Studio             | `http://127.0.0.1:1234/v1`  | 开发者面板启动本地服务器                       |
| llama.cpp             | `http://127.0.0.1:8080/v1`  | `llama-server`                                 |
| vLLM                  | `http://127.0.0.1:8000/v1`  | `vllm serve`                                   |
| Text Generation WebUI | `http://127.0.0.1:5000/v1`  | 需启用 OpenAI 兼容扩展                         |
| KoboldCpp             | `http://127.0.0.1:5001/v1`  |                                                |

### 怎么接

设置 → 模型连接 → **本地模型** → 自动扫描 → 勾选模型 → 加入。
也可以手动填一个非默认端口的地址再「探测」。

### 与云端连接的三处差异

1. **不要求 API Key。** `validModel` 放行 `local: true` 的空密钥；请求层在没有密钥时
   不再发送 `Authorization`（空的 `Bearer` 会让部分本地服务直接 401）。
2. **同一端点串行。** `ai-transport.mjs` 按 `baseUrl` 排队，一个本地端点同一时刻只跑一个请求。
   单 GPU 并发不会更快，只会让每个请求的首字节都变慢、互相触发看门狗。
3. **提示词按上下文裁剪。** 模型记录 `contextTokens`（8k/16k/32k/64k/128k），
   逐章写作时把提示词预算折算成 `contextTokens × 1.5 × 0.6` 字符——
   本地模型上下文小，不裁剪会直接把设定和前文挤掉。

安全边界：扫描只探本机与私有网段（`127.0.0.0/8`、`10/8`、`172.16/12`、`192.168/16`），
不会变成内网扫描器。

## 二、写作 Agent

### 四个阶段

```
构思 ──→ 起草 ──→ 自检 ──→ 修订
(JSON 节拍) (流式正文) (问题清单) (只改被指出的问题)
```

1. **构思**（`chapterBriefMessages`）：读本章大纲、前文结尾、人物、剧情线，
   产出 3~6 个场景节拍 + 关键转折 + 结尾落点 + 必须回收的伏笔 + 禁忌。输出严格 JSON。
2. **起草**（`chapterMessages` + `brief`）：把节拍作为「本章执行方案」注入正文提示词，
   与大纲冲突时以大纲为准。流式输出，前端实时可见。
3. **自检**（`chapterReviewMessages`）：以审稿编辑身份按六个维度挑问题——
   大纲落实、人物一致、连贯、节奏、AI 腔、篇幅。只报 high/medium，最多 5 条。
4. **修订**（`chapterFixMessages`）：带着问题清单改稿，要求「没被指出的段落不要动」，
   字数保持原稿 90%~110%。

### 降级链（每一步都不会让作者空手而归）

| 情况                          | 处理                                 |
| ----------------------------- | ------------------------------------ |
| 构思 JSON 解析失败 / 调用失败 | 跳过方案，直接起草                   |
| 初稿被 max_tokens 截断        | 不进入自检，按草稿保存并提示         |
| 自检调用失败                  | 保留初稿，把失败原因写进任务备注     |
| 自检无 high/medium 问题       | 直接用初稿，标注「自检通过」         |
| 修订被截断，或短于初稿 60%    | 判定「改坏了」，回退初稿             |
| 停笔 / 断流                   | 已生成部分存为草稿，覆盖前留版本快照 |

### 写作页入口

正文写作页 → 工具栏 **AI 写作**（`Ctrl / ⌘ + J`）：

- 四种方式：写整章 / 续写 / 润色 / 按问题改
- 可临时换模型（含本地模型），默认跟随本书
- **深度写作**开关：只有「写整章」可开，关掉就退回一次性生成
- 产物先进入预览区，作者点「采用到正文」才写入编辑缓冲——
  服务端用 `previewOnly` 走 proposal 通道，**不直接覆盖章节**
- 面板里可展开查看「写作方案与自检意见」，知道 AI 为什么这么改

### 接口

`POST /api/generate/chapter`

```json
{
  "novelId": "...",
  "chapterIndex": 3,
  "kind": "write | continue | polish | revise",
  "extraPrompt": "…",
  "modelId": "...",
  "previewOnly": true,
  "agent": true,
  "agentDepth": "full | draft"
}
```

任务对象新增字段：`stage`（plan/draft/review/revise/done）、`stageNote`、`brief`、
`review`、`revised`。
